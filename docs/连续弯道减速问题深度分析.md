# 连续弯道减速问题深度分析

## 问题根源确认

基于Agent的深入分析，我已经确认了连续弯道减速问题的具体机制：

### 1. 减速调用点分析

**主要问题位置**：
- **EntityCartBasic.java第216行**：`this.applyDrag();`
- **CartBaseMaintenance.java第197-201行**：实现DRAG_FACTOR = 0.9的减速
- **LinkageHandler.java第227-230行**：联挂车辆额外减速LINK_DRAG = 0.95

### 2. 减速累积效应

```
初始速度: 1.0
第1个弯道: 1.0 × 0.9 = 0.9 (applyDrag)
第2个弯道: 0.9 × 0.9 = 0.81 (applyDrag)
第3个弯道: 0.81 × 0.9 = 0.729 (applyDrag)
第4个弯道: 0.729 × 0.9 = 0.656 (applyDrag)
```

经过4个连续弯道，速度衰减到原来的65.6%，这明显不符合物理规律。

### 3. 多重减速机制

```java
// 位置1: EntityCartBasic.moveAlongTrack 第216行
this.applyDrag();  // 乘以0.9

// 位置2: CartBaseMaintenance.applyDrag
protected void applyDrag() {
    super.applyDrag();
    this.motionX *= DRAG_FACTOR;  // 0.9
    this.motionZ *= DRAG_FACTOR;

// 位置3: LinkageHandler.adjustCart 第227-230行
if (linked && !HighSpeedTools.isTravellingHighSpeed(cart)) {
    cart.motionX *= LINK_DRAG;  // 0.95
    cart.motionZ *= LINK_DRAG;

```

### 4. 已实施的修复

**修复内容**：
- 删除了`EntityCartBasic.java`第216行的重复`applyDrag()`调用
- 这样避免了在基类已经调用`applyDrag()`的情况下重复减速

**修复原理**：
1. 基类`EntityMinecart.moveAlongTrack`在方法末尾已经调用了`applyDrag()`
2. EntityCartBasic重写的方法中又调用了一次，导致重复减速
3. 移除这次重复调用，确保每帧只应用一次减速
